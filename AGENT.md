# Agent Guide

## Scope

- Keep `main.py` focused on CLI parsing and dispatch.
- Put reusable implementation logic under the `nga_tools` package.
- Keep NGA API fetching logic inside `nga_tools/ngaclient`.
- Avoid duplicating logic between top-level scripts and package modules.

## Guide Maintenance

- If this file appears outdated or inconsistent with the current project, tell
  the user what seems wrong and suggest an update.
- Do not edit this file unless the user explicitly permits changing it.

## Commands

- Use pixi for project commands.
- Run the CLI with `pixi run python main.py ...`.
- Run strict type checking for package code with `pixi run typecheck`.
- Run syntax checks with `pixi run python -m py_compile <files>`.

## Dependencies

- Keep shared dependencies in `[dependencies]` in `pixi.toml`.
- Keep platform-specific dependencies under `[target.<platform>.dependencies]`.
- Linux-only PDF support belongs under `[target.linux.dependencies]`.
- Do not assume `weasyprint` exists outside the pixi environment.

## Configuration And Outputs

- Do not commit local `config.json`, `secrets.json`, cookies, downloaded output,
  generated PDFs, images, or temporary JSON exports.
- Use `config.example.json`, `secrets.example.json`, and `nga_tools.config` as
  the tracked contract for config keys.
- Keep sensitive config such as NGA cookies in `secrets.json`; keep non-sensitive
  runtime settings in `config.json`.
- Preserve `thread_configs.json` unless the user explicitly asks to modify saved
  thread data.

## Code Guidelines

- Add type annotations for new or moved package code.
- Keep strict Pyright clean for code under `nga_tools`.
- Prefer small modules with clear ownership over adding more logic to `main.py`.
- Keep network access, file writes, HTML conversion, image handling, and PDF
  generation separated when moving code into the package.
- Preserve existing CLI behavior unless the user explicitly asks for a behavior
  change.
